# DATA.md — 数据存储与查询指南

> 最后更新: 2026-10-15 · commit `fe26fa1`

## 1. 数据实体清单

全部数据是**本机 Markdown / JSON / 锁文件**，集中在 `~/.opencode/`（core 层 11 处硬编码，路径清单见 modules/store.md §文件族）。

| 实体 | 位置 | 内容 | 写入方 |
|------|------|------|--------|
| 用户画像 | `~/.opencode/USER.md` | Track 1，四固定分类条目 | `store/user-md.ts`（每次提炼备份 5 版） |
| 记忆索引 | `~/.opencode/MEMORY.md` | Track 2，`## <slug>` 分节的链接列表 | `store/memory-md.ts` |
| 记忆卡片 | `~/.opencode/projects/<slug>/.mem/*.md` | 单条记忆（frontmatter + Why/How to apply） | `store/memory-md.ts` / `memory-write.ts` |
| 回收站 | `~/.opencode/projects/<slug>/.mem/.trash/<file>.<ts>` | deprecate/forget 的软删件 | deprecate / forget |
| 协议产物 | `~/.opencode/memx-protocol.md` | 信号协议（真源 `src/core/protocol-template.ts`） | `scripts/sync-protocol.ts`（幂等） |
| 配置 | `~/.opencode/memx.config.json` | 运行配置（每次提炼即时重读） | 用户手写 |
| 备份 | `~/.opencode/*.bak.<ts>` | USER.md / MEMORY.md 各留 5 版 | 写盘前自动 |
| 锁 | `~/.opencode/.USER.md.lock` / `.MEMORY.md.lock` | 跨进程锁（正常路径不长期存在） | `store/lock.ts` |
| 报警账本 | `~/.opencode/memx-alerts.json` | 报警事件数组（封顶 200、剪龄 7 天）——**报警单一事实源** | `core/alerts.ts`（宿主注入） |
| 同步仓 | `~/.opencode/memx-sync-repo/` | Git workdir（镜像 USER.md / MEMORY.md / `.mem/**/*.md`） | `core/sync.ts`（仅 sync 启用时） |
| 同步状态 | `~/.opencode/memx-sync-state.json` | `lastPushAt` / `lastPullAt` / `consecutiveFailures` / `lastError` / `lastPiiScan` | `core/sync.ts` |
| 同步锁 | `~/.opencode/.memx-sync.lock` | push/pull 串行闸门（ttl 10 分钟 / 等锁 5 分钟） | `core/sync.ts` |
| 宿主入口 | `~/.config/opencode/plugins/memx.ts` | `export { default } from "<repo>/src/hosts/opencode/index";` | install.sh |
| 宿主依赖声明 | `~/.config/opencode/package.json` | zod / @opencode/plugin / @opencode/client v2 | install.sh（v1→v2 名自愈） |
| 诊断 + 游标 | OpenCode sqlite kv（`ctx.storage`） | `diag:<slug>` / `cursor:<sessionID>` | index.ts |

## 2. 格式

### USER.md（受管部分）

```markdown
# User Profile & Style

> Auto-generated by memx. Last updated: 2026-07-29

## 沟通与交互风格
- [2026-07-29] 先给结论，再展开推导过程

## 工具与环境偏好
- [2026-07-25] 使用 pnpm 而非 npm/yarn

## 踩坑与禁忌
- ~~[2026-07-15] 偏好 Vue 3 Composition API~~ (Deprecated: 已迁移至 Svelte)
```

规则：条目 `- [YYYY-MM-DD]` 开头；废弃用删除线不物理删除；四个固定分类标题不可新增；硬限 200 行。**非受管内容（preamble / section.extras）原样保留**。

### MEMORY.md 索引（受管格式 `- [title](path) - hook`）

```markdown
## root-project-foo
- [auth rewrite](~/.opencode/projects/root-project-foo/.mem/project_auth_rewrite.md) - auth middleware rewrite driven by compliance
```

### 记忆卡片

```markdown
---
name: auth rewrite
description: auth middleware rewrite driven by compliance
type: project
---
Rewriting auth middleware for compliance.

**Why:** Legal flagged session token storage.
**How to apply:** Scope decisions favor compliance over ergonomics.
```

四类 type：`project`（进行中的工作）/ `reference`（外部资源指针）/ `feedback`（协作指导，强制 Why+How）/ `user`（用户背景）。

### slug 规则（`core/memory-types.ts` 的 `deriveSlug`）

目录路径去首尾 `/`、`/` → `-`。`/root/project/foo` → `root-project-foo`。**工作目录路径避免空格/中文/特殊字符**，否则 slug 难看且难排查。

## 3. 常见查询场景

| 我想查 | 去哪 | 怎么查 |
|--------|------|--------|
| 画像现在记了什么 | `~/.opencode/USER.md` | 直接打开；废弃条目带删除线 |
| 某项目有哪些记忆 | `~/.opencode/MEMORY.md` 找 `## <slug>` 节 | 或打开对应 `.mem/` 目录 |
| 某条记忆的完整内容 | 索引里的链接 | 打开对应 `.mem/*.md` |
| 插件真实运行状态 | **sqlite kv 表**（不是 memx_status 的回执） | 见 §4 诊断 |
| 某会话的捕获进度 | kv 的 `cursor:<sessionID>` | 同上 |
| 写坏了想回滚 | `~/.opencode/*.bak.<ts>` | 按时间戳选版本覆盖回去 |
| 被删掉的记忆 | `.mem/.trash/<file>.<ts>` | 改回文件名并重新登记索引 |
| 有哪些报警、要不要销账 | `~/.opencode/memx-alerts.json` | 或跑 `pnpm run doctor` 看 counts + 最近 10 条；销账 `pnpm alerts:clear --code=X` |
| 同步开了没、上次推拉何时 | `pnpm run doctor` 的 sync 段 | 或直读 `~/.opencode/memx-sync-state.json` |
| 哪些文件会被同步 | `pnpm sync:dry-run` | 只读预览（含双向行数 / PII 命中）；**永不 push** |
| 首合并前远端有什么 | `pnpm sync:dry-run -- --fetch` | 先取远端到 workdir（不碰 `~/.opencode` 记忆文件） |

## 4. 诊断查询（排查"它怎么又没记住"）

**第一步永远先跑 `pnpm run doctor`**——只读面板四段（alerts / memory files / opencode diag / sync），不联网、不写盘、退出码恒 0。⚠️ 别用 `pnpm doctor`（pnpm 有同名内建命令，会静默跑成 pnpm 自检）。

`memx_status` 工具只打固定字段；`evtCounts` / `lastCapture` / `rawContext` / `health` 只在 kv 行里（**`alerts` 例外**：以账本文件 `memx-alerts.json` 为准，kv 里那份是只写镜像）：

```bash
sqlite3 ~/.local/share/opencode/opencode.db \
  "SELECT value FROM kv WHERE key LIKE 'plugin:%'"
```

（namespace = `plugin:` + "memx" 逐字符 4 位十六进制；键已按目录隔离为 `diag:<slug>`。）注意：**同目录多实例仍会互相覆盖**（`opencode run --server` 客户端也会实例化插件），排查优先看 serve 日志：`~/.local/share/opencode/log/opencode.log`（成功写盘搜 `Updated USER.md` / `Updated MEMORY.md`；LLM 原始返回搜 `llm raw(N):`，400 字符截断）。

## 5. 数据变更链路

| 谁写入 | 写到哪 | 谁读取 |
|--------|--------|--------|
| 后台提炼（refine/refineMemory） | USER.md / MEMORY.md + .mem | 下一 step 的 context hook 注入 |
| memory_write 工具 | 同上（同一条写路、同一把锁） | 同上 |
| forget / deprecate | 移入 .trash + 索引改条目 | 注入的索引随之更新 |
| health auto-fix | MEMORY.md 索引（同锁内） | 同上 |
| 报警（`recordAlert`） | `memx-alerts.json`（事实源）+ kv `diag.alerts`（镜像）+ MEMORY.md 首行面包屑 | doctor / `memx_status` / **模型**（面包屑随索引被注入） |
| 云同步 push | `memx-sync-repo/` → 远端 Git 仓（USER.md / MEMORY.md / `.mem/**`） | 其他机器的 pull；状态被 doctor 读取 |
| 云同步 pull | 本地记忆文件（远端优先；本地差异先存 `.bak.<ts>`） | 下一 step 的 context hook 注入 |
| 主 AI（❗非 memx 行为） | 可能自行写 AGENTS.md 等文件 | 宿主指令组装——**这是所有权缺口，协议 v1.1.0 规则 9 是软约束** |

**多宿主并发**：文件锁（mtime TTL + 锁内重读）已覆盖"两个进程同时读改写同一文件"；未来 DSH 壳将共享 `~/.opencode/` 数据目录（2026-10-13 拍板，见 DSH-ADAPT.md）。
